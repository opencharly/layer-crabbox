## Summary

**The Crabbox CLI pin moves from `0.51.0` to `0.78.0`**, which is the substance of [opencharly/layer-crabbox#6](https://github.com/opencharly/layer-crabbox/issues/6).

The pinned CLI did not accept `--provider` on `doctor` or `providers`, while the upstream README documents it — so a consumer could not pass a provider selection through, and the failure was an **unknown flag** rather than a wrong value. `plugin-crabbox`'s R10 bed measures exactly that:

```
FAIL  the provider selection reaches the CLI, and doctor accepts it   [crabbox-doctor-firecracker-provider]
```

Upstream is at **`v0.78.0`**, twenty-seven releases on. Diff, read from `git diff --stat` before this body was written — **one file, 5 insertions / 5 deletions** — the fifth being the escaped matcher the previous verdict found — and every changed line is a version string:

| line | change |
|---|---|
| `CRABBOX_VERSION` | the pin itself, which the download URL derives from |
| the candy's own check | `crabbox --version reports the pinned 0.78.0 release` |
| the README table | `pinned \`0.78.0\`` |
| a prose mention | *the v0.78.0 surface* |
| **the escaped stdout matcher** | `matches: "0\\.51\\.0"` → `"0\\.78\\.0"` — found by the **verdict**, not by my substitution |

**Five lines changed in total, and the fifth was found by the verdict — which is the honest part of this revision.** The fifth is the check's *stdout matcher*:

```yaml
- check: crabbox --version reports the pinned 0.78.0 release on stdout
  stdout:
    - matches: "0\.51\.0"     # ← the escaped form, which a substitution for 0.51.0 cannot see
```

It is the same version with an **escaped dot**, so `sed 's/0\.51\.0/…/'` walked straight past it — and the consequence was not cosmetic: after this PR installs the 0.78.0 binary, `crabbox --version` emits `0.78.0`, that regex stops matching, and **the candy's own plan check — the very check this PR rewrote the text of — would fail**. The change would have broken the thing it fixes. It is corrected in the same tree, and the sweep is now claim-keyed against *every* form of the old version:

```
$ grep -n '51' charly.yml
(no output)
```

That is the argument for substituting *and* for then grepping for what the substitution could not see: it finds what you do not know is there.
