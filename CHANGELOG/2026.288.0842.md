### One methodology note, because it nearly shipped a wrong conclusion

My first sweep of this repo used `git grep … | head -12`, and `CHANGELOG` sorts before `README`, so the README's hits were **truncated away** and the output read as if the claim lived only in history — i.e. as if this issue were already fixed. I only caught it by re-reading the file directly. The umbrella rulebook's command hygiene already forbids exactly this shape (`grep -m N`, never `grep | head`), and the near-miss is recorded here rather than omitted because the next reader of this repo will run the same sweep on the same file layout, where `CHANGELOG/` comes first alphabetically every time. The sweep above is unpiped and prints its own exit code.
