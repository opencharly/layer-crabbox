# 2026.288.2114 — docs(crabbox): state the install's deliberate narrowing, and what it costs

## Summary

One new section in `README.md` (21 lines, no other file touched) stating a property of this install that nothing documented: **the install extracts only the `crabbox` binary from the release archive**, and upstream's archive also carries a *native* runtime pack.

```yaml
# charly.yml — unchanged by this PR
36:              extract_include: [crabbox]
75:            | Install | `download:` the release tarball, `extract_include: [crabbox]` |
```

What that pack is comes from upstream's own `CHANGELOG` at the pinned `v0.78.0`, quoted in the README rather than paraphrased:

> "Complete installations now include a native runtime pack. … the Linux companions let independent Linux and WSL2 SSH commands **run without Bash**."

So it is **CLI-side command supervision**, and the cost of omitting it is bounded and now stated:

- **not needed** on any target with Bash — and this candy composes into Fedora, Arch, Debian, Ubuntu and CachyOS boxes, all of which ship Bash, so the narrowed install is sufficient for leasing containers and driving a local coordinator;
- **needed** on a Bash-less Linux target (WSL2, a minimal/Alpine guest, a Bash-less runner), where independent argv execution requires the pack and `crabbox --preflight --preflight-tools default,bash` reports the absent state.

**Why `README.md` and not the candy.** `README.md` is this repo's user overview — "how to install/run/use it" — and this is install documentation. No candy field, version, `plan:` step or assertion changes, so the projected `/charly-tools:crabbox` skill is not stale and the corpus owes no regeneration. I have deliberately **not** edited `charly.yml`, on that reading; if a reviewer reads this repo's "edit the candy entity and the skill entity together" as covering install prose, say so and I will mirror it — but mirroring it would make the change a config change with a corpus gate, which is why I am stating the reasoning here rather than leaving it implicit.

**Provenance, because this finding has a history.** It began as my claim that the install drops a "`crabbox-runtime` capability pack". That name was **invented, not read** — there is no such path at `v0.78.0` (`runtimes/` is the real one, containing `aws-lambda-microvm`) — and I retracted it. My replacement hypothesis (provider-side venue artefacts) was also wrong. Only upstream's own release notes settled it. `opencharly/layer-crabbox#8` carries all three corrections.
